# 评分标尺与校准

> 每题 0-3 分，固定标尺，禁止"感觉分"。分数是级别校准和排期的唯一输入。

## 单题标尺（0-3）

| 分 | 标准 | 排期 |
|---|---|---|
| **3** | 要点齐全 + 追问 1-2 问全过 + 给出可验证的手段/例子（对齐 Full answer） | +30 天毕业 |
| **2** | 主干正确但浅：缺边界、缺验证、追问答一半 | +3 天 |
| **1** | 沾边：方向对但机制错/含糊，或只答出 Short answer 的第一层 | +1 天 |
| **0** | 没答出、答反、或命中 Wrong answers 里的典型错误 | 明天重考 |

### 各题型的"主干"指什么

| kind | 必须出现的要点 |
|---|---|
| concept | 机制的因果链（A→B→C），至少一个"如果不这样会怎样" |
| debug | 症状→根因→**怎么证实**（三件缺一扣到 1 分以下） |
| trade-off | 两侧的边界条件 + 在什么约束下选哪边 |
| estimate | 明确假设 + 量级运算过程（只报数字给 1 分） |
| code reading | 指出具体行/具体操作 + 它会在什么输入下炸 |
| design | 需求→约束→组件→**怎么验证达标**（缺验证最多 1 分） |
| incident | 排查链证据驱动，答案里带得出数据（token 数、百分比、flag 值） |
| behavioral | STAR 齐全 + 有你自己的决策与量化结果 |

## 追问规则

1. 从该题 frontmatter 后的 **Follow-ups** 里挑，按目标级别取：
   - 目标 1 Screen → 挑标注 Level 1 的追问 1 问
   - 目标 2 Working → Level 2 挑 1-2 问
   - 目标 3 Senior → Level 2 全过才上 Level 3
   - 目标 4 Staff → 一路追问到用户开始含糊，含糊处即为当前真实级别
2. 追问答砸不改判整题 0——**主干分和追问分分开记**：`log <id> --score X --followup 0|1`，校准只信追问分
3. 每次追问只加压一层，用户明显崩了就停，记录"崩在哪一层"

## 错误答案（Wrong answers）的用法

- 对完答案后，从 Wrong answers 里挑**最接近用户实际说法**的一条，问他："这条为什么错？"
- 答得上 → 此题维持原分；答不上 → 主干分再降 1（下限 0）
- 这一步是防"蒙对"：分数必须经得起反向检验

## 级别校准（整轮后做）

按轮次得分率（得分/该轮满分）对照：

| 得分率 | 判定 |
|---|---|
| ≥90% 且追问无崩 | 该轮达到目标级别，稳 |
| 70-89% | 边缘——弱项卡 Top3 刷 3 天再测 |
| 50-69% | 低半级：目标级别降 0.5 重新排计划 |
| <50% | 低一级：回对应 lessons 补学，两周后再摸底 |

**校准的三条铁规：**
1. 只信分数和追问，不信自我感觉
2. 同一张卡两道题都 ≤1 分 → 该卡整体标红，进补学清单
3. behavioral 轮单独算——技术分再高，STAR 不过关就是不过关

## 分数记录格式（interview.py）

```bash
python scripts/interview.py log <id> --score 2 --followup 1 --note "缺验证手段"
```

`status` 输出各岗位卡的平均分与红牌卡；`weak` 直接列出 0/1 分且未毕业的题（按卡聚合），即弱项补学清单的原始数据。
